# Lineage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Lineage, a FalkorDB-backed company brain over the public Python project. Its Historian agent answers *why / who / since when* questions with evidence subgraphs. Its Steward agent propagates change along `DERIVED_FROM` lineage into every agent's memory, blocking stale actions. A what-if service forks the graph to show what breaks when someone leaves.

**Architecture:**
- **Data:** deterministic ingestion of public sources (peps.json, PEP rst, devguide experts index, discuss.python.org JSON, CPython GitHub) into `lineage:company`.
- **Agents:** each agent and user has its own FalkorDB graph, isolated by Redis ACL. Lineage crosses graphs through `Evidence {ref}` stub nodes. Counterfactuals use `GRAPH.COPY` forks.
- **Interfaces:** a FastAPI backend serves a Next.js + Cytoscape UI and an MCP server.

**Tech Stack:** Python 3.12, uv, `falkordb` (async), FastAPI, `anthropic` (`claude-sonnet-5-5`), `fastembed` (bge-small-en-v1.5, 384-d), `httpx`, `docutils`, `mcp` (FastMCP), pytest + pytest-asyncio. Next.js 15 + Cytoscape.js. Docker Compose. Railway (API + FalkorDB) and Vercel (web).

**Spec:** `docs/specs/2026-10-14-lineage-design.md`. Read it first. Section numbers below (§) refer to it.

## Global Constraints

- **Event window:** 2026-10-15 00:01 IST to 2026-10-18 23:59 IST. Submission complete by **2026-10-18 22:00 IST**, leaving a 2-hour buffer.
- **FalkorDB is the primary datastore.** It holds every node, edge, embedding, memory, task and fork. No other database.
- **FalkorDB Docker image is pinned** to `falkordb/falkordb:6.0.2` (verified 2026-10-14, native arm64 + amd64). Never `latest` or `edge` in compose or deploy. Server args: `MAX_QUEUED_QUERIES 25 TIMEOUT_DEFAULT 5000 TIMEOUT_MAX 30000 RESULTSET_SIZE 10000`. See `docs/research/2026-10-14-data-sources.md`.
- **Python 3.12.** Package management with `uv`. Async FalkorDB client `from falkordb.asyncio import FalkorDB`.
- **Graph names** (exact):
  - `lineage:company`
  - `lineage:agent:historian`
  - `lineage:agent:steward`
  - `lineage:user:<uid>`
  - `lineage:shared`
  - `lineage:fork:<uuid8>`
  - tests use `test:<uuid8>`
- **Stable node ids** (exact formats):
  - `pep:<n>`
  - `person:<github-or-slug>`
  - `area:<name>`
  - `chunk:pep:<n>:<i>`
  - `decision:pep:<n>:<kind>`
  - `thread:<topic_id>`
  - `post:<post_id>`
  - `pr:<n>`
  - `event:<slug>`
  - `team:<slug>`
- **Vector index:** cosine, 384 dimensions, `vecf32`. `db.idx.vector.*` `score` is a **distance**, where lower means more similar. Similarity = `1 - distance`.
- **Every write is batched** with `UNWIND $rows` plus `MERGE` on `id`. Ingest is idempotent.
- **Data:** only public sources from spec §2. Raw responses cached under `data/raw/` and committed so deploy ingest needs no network.
  - Synthetic data carries `synthetic: true`.
  - Discourse: at most 1 request/s.
  - GitHub: authenticated, with search requests spaced ≥ 2.1 s apart.
- **Privacy:** person-level metrics are never shown as a ranked list. Ownership and departure results are presented per area.
- **Query timeouts:** set `TIMEOUT_DEFAULT` to 5000 ms on the server. Tool queries must finish within it.
- **Historian limits:** at most 6 tool calls per question. Citations must be ids present in that question's tool evidence.
- **Where Cypher lives:** all of it is in `lineage/graph/queries.py` as module-level named constants, each with a docstring-style comment explaining intent.

## Review Focus

1. **Same person, different names.** "Guido van Rossum" (PEP author), `gvanrossum` (experts index) and Discourse `guido` must become one `Person`. Two different people with similar names must not merge. *Test owned by Task 4.*
2. **Re-running ingestion.** A second full ingest run must leave node and edge counts unchanged, with no duplicate Decisions or edges. *Test owned by Task 9.*
3. **The LLM cites ids it never saw.** Invalid citations are dropped. If none remain, the Historian abstains instead of answering. *Test owned by Task 13.*
4. **Ripple safety.**
   - Cyclic references (A→B→A) must terminate.
   - Applying the same Event twice must yield the same stale set, with no duplicate FixTasks.
   - *Tests owned by Tasks 15 and 16.*
5. **Out-of-corpus and before-it-existed questions.** These must produce an abstention. A PEP created after an `as_of` date must not appear in results. *Tests owned by Tasks 11 and 13.*
